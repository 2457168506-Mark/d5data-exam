# 奖池分账修复说明

## 1. 问题复现

`split_pool_0` 保留了原始实现，用于对照测试：
print(split_pool_0(10000, [1, 1, 1]))最终结果[3333, 3333, 3333]
每个人独立取整后，没有处理尾差，所以总金额可能不等于奖池。

### 出错输入

- 输入：`pool_cents = 10000`，`weights = [1, 1, 1]`
- 原返回值：`[3333, 3333, 3333]`
- 实际的和：`9999`
- 应有的和：`10000`

结果是少发了 `1` 分。

## 2. 修改方法

修改后的 `split_pool` 使用最大余数法：

1. 先计算每个人按权重应得的份额。
2. 对份额向下取整，先分配整数部分。
3. 计算还剩多少分没有分配。
4. 余数大的人优先补 `1` 分，直到剩余金额分完。
5. 余数相同时，原来的先后顺序不变，保证结果固定。

在总权重大于零的正常业务输入下，这样既能保证所有人的金额之和等于奖池，也能保证每个人与向下取整的基础份额最多相差 `1` 分。
